- [x] **One taxonomy: 28 tags.** Categories merged into tags and deleted; 33 near-duplicate

      author box and comments; those are still not carried across.

## Theme

The theme is hand-written: **184 lines** across one stylesheet and four layouts, carrying
the old BMag look (Bitter, white ground, charcoal nav, the `#77AD0A` olive accent) with a
three-state Auto/Light/Dark toggle the original never had.

- [ ] **Compare features against chulapa** and decide what is worth building. The
      WordPress site had things this does not:

      | Feature | WordPress had | Now | chulapa would give |
      |---|---|---|---|
      | Search | yes | **yes**, `/search/` | lunr, built in |
| Card hover previews | yes (tooltip plugin) | **yes**, `assets/js/autocard.js` | n/a |
      | Related posts | yes (plugin) | no | built in |
      | Author box | yes | no | built in |
      | Comments | yes | no | disqus / giscus |
      | Social share | yes (sexybookmarks) | no | built in |
      | Tag / category pages | yes | yes | yes |
      | Pagination | yes | yes | yes |
      | RSS / sitemap | yes | yes | yes |

      The trade is maintenance against capability. 184 lines has no upgrade treadmill, but
      during the teamserio.us migration chulapa cost us a Bootstrap 4-vs-5 collapse, a
      breaking 1.x→2.x upgrade, absolute URLs loading production CSS into previews, and a
      plugin collision that silently broke search. Decide deliberately rather than by
      drift — and note that switching later is cheap precisely because it is 184 lines.
- [x] **Search.** Done without lunr. 46 posts of full text is ~61 KB gzipped, which is
      smaller than lunr.js alone, so `/search/` scores the index itself: title and tag hits
      outrank body hits, all terms must match, and results carry a highlighted snippet.
      `search.json` is generated by Jekyll; the page is plain JS with no dependency.

      Two WordPress artefacts had to be handled, both of which silently broke matching
      before they were fixed: 2,975 HTML entities that `strip_html` leaves behind (so
      snippets read `I&#8217;m`), and curly quotes in the post bodies (so a search for
      `didn't` typed with a plain apostrophe found nothing — it now returns 10 posts).

## Outbound link rot

Sixteen years of posts, **2,457 outbound links across the 46 kept posts** (550 distinct,
33 hosts).

- [x] **Link checker built**: `script/check-links.py`, report in
      [link-report.md](link-report.md). Also `script/check-cards.py`, which verifies every
      Magic card name against Scryfall — that found 10 misspellings (`MoxPearl`,
      `Mycosinthe Lattice`, `Dig-Through Time`, `Cursed Scrolls` and friends), all fixed
      and all now landing on the right card page.
- [ ] **Run the checker in CI** so new rot surfaces on its own rather than being found by
      a reader. Both checkers hit third-party hosts hundreds of times and get
      rate-limited, so this wants a weekly schedule, not a per-push hook.

- [ ] **Repoint the five Mana Drain links once those reports are ported.** These posts
      link to TSI/TSO result threads on `themanadrain.com`, which 404 since the forum
      reorganised, so they currently point at Internet Archive snapshots:

      | post | TMD thread |
      |---|---|
      | `ad-naus-at-my-first-tsi-mishras-on-the-maumee` | `#1639` tsi mishra's by the maumee 12-2-2017 |
      | `tso-03-feb-2018-dragon` | `#1738` team serious open 2-3-18 at the pop shop |
      | `tsi-hazard-ravager-goes-to-columbus` | `#1763` tsi hazard's birthday 3.0 2-17-2018 |
      | `ospb2019` | `#2786` tsi the land 6-15-2019 |
      | `tso-2022-07-23-paradoxical-outcome` | `#3824` — **already ported: [teamserio.us/posts/20220723_tso-all-american-warren](https://teamserio.us/posts/20220723_tso-all-american-warren)** |

      teamserio.us is porting those reports out of the archive — all five threads are in
      its `docs/tmd-archive-reports.md` inventory (teamserio.us PR #27). As each lands
      there, swap the snapshot link for the live teamserio.us post. An archive snapshot is
      a fallback; a working link to the real write-up is better.

**Current state: 0 dead links of 118 checked**, down from 33, plus one host that blocks
robots and was verified by hand. See [link-report.md](link-report.md).

Getting there needed three fixes to the checker itself, each of which had been
manufacturing false positives:

- **urllib does not follow 308.** Any site answering a permanent http→https redirect with
  308 read as dead. `surpasshosting.com` was reported dead and is fine.
- **Minimal headers get stalled.** `npr.org` timed out after 60 seconds with just a
  `User-Agent`, and answered in 0.6 s once `Accept` and `Accept-Language` were sent.
- **`TimeoutError` is not a `URLError`,** so the retry-with-GET path never ran for the
  links that most needed it.

And one fix to the posts: nine links to `eternalcentral.com` were dead because **the
migration's own URL rewrite had mangled them** — the `/wp-content/uploads/` →
`/assets/images/` rule was applied to absolute URLs on other people's sites, not just
local ones. All nine are alive at their original path and have been restored.
- [x] **Policy decided and applied: Internet Archive where possible.** 18 dead links now
      point at a snapshot, chosen closest to the date of the post that links it, so a 2018
      tournament report gets the forum thread as it looked in 2018. Where no snapshot
      exists — 5 Twitter links to accounts that are gone from x.com too — the `<a>` was
      dropped and the text kept, because the text carries the meaning on its own ("Nat
      Moes", "I even made Top 8", "@m_steve_m"). Run with
      `script/archive-dead-links.py --apply --unlink`.

      **One link is left alone deliberately:** `facebook.com/DanielAltersMagic` answers 400
      to anything unauthenticated, but **loads fine in a browser** (confirmed 2026-10-09).
      Blocked is not the same as rotted. It is listed in its own section of the report
      rather than counted as dead, so one permanent false positive does not sit at the top
      of every future run.

**The deckbox concentration is gone.** It used to account for 2,273 of the 2,457 links —
everything the Magic card-tooltip plugin touched — so if deckbox had stopped, every
decklist on the site would have lost its links at once. All of them now point at
`scryfall.com/search?q=<name>`, matching teamserio.us, and the 49 hotlinked card images are
24 local files under `assets/images/cards/`. `_plugins/mtg_autocard.rb` keeps new posts on
the same footing: `<<Card Name>>` or `((Card Name))` becomes the same Scryfall link.

The URL form is `/search?q=`, not `/card?q=` — `/card` is not a Scryfall endpoint and
404s. teamserio.us had that wrong in its own plugin; fixed there in PR #26.

Other hosts worth attention: `deckstats.net` (90), `twitter.com` (27 — many now
unreachable without an account), `eternalcentral.com` (17), `t.co` (5, shortener).

**Known dead, needing a policy decision:** every `themanadrain.com` forum topic 404s (5
links — the forum reorganised and took the event results with it), and
`capcitybrew.com/amberwaves.php` is gone. Remove, leave as plain text, or point at an
Internet Archive snapshot.

## Backup

Covered in [backup-and-restore.md](backup-and-restore.md). The archive is on phatmyth and
in pCloud, and that file documents how to bring a single post back.

- [ ] **Read the unpublished posts.** Counted directly from `wp_posts` in the dump:
      **84 drafts and 2 private**, against 152 published. Never reviewed — the triage
      wizard covered published posts only. By content length, 40 have 200+ characters,
      **19 have 500+**, 16 have 1000+; the rest are stubs and link-dumps.

      Most of the 17 are old sysadmin notes (`DL385 G1`, `Linux KVM`,
      `Configure Postfix to Use Gmail SMTP`, `Sharp Zaurus and Wireless Security`). Two are
      Magic, which is what this site is now about: **`Grim Dragon`** — at 8,284 characters
      the longest unpublished thing we have — and **`Eternal Weekend 2019`**. Those two are
      worth reading first.

      Read them with `script/wp-posts.py` — it parses the dump directly, no MySQL needed:

      ```
      script/wp-posts.py --counts                  posts and pages by status
      script/wp-posts.py --list draft --min 500    the substantive ones
      script/wp-posts.py --show grim-dragon        one post's body
      ```

      ⚠️ **One of the drafts contains credentials** — an NZBGeek API key and a MusicBrainz
      access token, on their own labelled lines. **Both were rotated on 2026-10-09**, so the
      strings in the archive are dead. They were never in git and never on the live site.
      Strip them before publishing that draft anyway: dead keys in a public post are noise
      at best and a bad habit at worst.

      It is deliberately not named here, because this repo is public and naming it would
      point at the one draft worth not advertising. Find it with the scan in
      [backup-and-restore.md](backup-and-restore.md#checking-a-draft-for-credentials), which
      is more reliable than a remembered title in any case. A scan of all 86 unpublished
      posts found no others; the 32-hex strings in `SGH-T989 101` are ROM checksums, not
      keys. The 46 migrated posts and every tracked file are clean.
- [ ] **Re-verify the pCloud copy periodically.** A backup nobody has restored is a guess;
      this one was restore-tested once, on 2026-10-09.

## Media management

The same considerations as teamserio.us, which ran into the GitHub Pages **1 GB published
site limit** mid-migration. Currently 334 files, 86 MB — comfortable, but the rules should
exist before a photo-heavy post arrives, not after.

- [x] **Full-resolution originals are archived** on resize, to `assets/originals/`,
      which `_config.yml` excludes from the build so it costs nothing against the 1 GB
      Pages limit. Nothing is in there yet because **nothing currently needs resizing** —
      all 318 images are inside the 2560px cap and the largest is 1.9 MB; the WordPress
      migration already downsized everything (133 MB → 89 MB).

      The trigger had to be fixed to work here at all. teamserio.us only archives
      `DSC_*`, which is what its DSLR produces — **this site has zero of those.** Its
      photos came through WordPress as `IMG_*` (35), `P#######` (7) and
      `YYYY-MM-DD-HH.MM.SS` (76), so the ARCHIVE bucket never fired and an oversized
      photo would have been resized in place with the original lost. Verified with probe
      files: all four camera-name styles now archive, while a non-photo graphic still
      resizes in place.
- [x] **A size guard in CI.** Confirmed present in `deploy-pages.yml` and
      `build-check.yml`: fails the build over 900 MB, warns over 500 MB. Both workflows
      also check that every referenced image and thumbnail actually resolves.
- [ ] **Watch the WordPress thumbnail variants.** 154 of the 334 files are WordPress's own
      `-WxH` renditions, which the migrated gallery markup references by exact filename.
      `prep-images.sh` exempts them for that reason. If galleries are ever re-rendered,
      those files become dead weight and should go.
- [ ] **Decide the policy for new posts.** Image prep runs in CI on branches; the rule is
      the same as teamserio.us — drop photos in, commit to a branch, let CI resize.
